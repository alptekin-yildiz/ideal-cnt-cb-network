# GF mechanism support tables

This directory holds the compact numerical support package for the manuscript's
GF mechanism/sign-flip discussion, Fig. 10, and Table 3. It lives under
`data/article_evidence/` because it is a derived evidence chain, not one of
the regenerated stage anchors in `data/reference/`.

These tables are intentionally separate from `data/reference/gf/`. The main GF
reference set reports the ideal affine response. The files here report a later
phenomenological mechanism campaign that asks how high resistance-based GF can
become if selected junction families acquire an additional strain-driven
opening term.

The mechanism is diagnostic, not a calibrated damage model. Its key conclusion
is that high GF requires opening the current-carrying CNT-CNT junctions: CB-CNT
and CB-CB opening do not flip the sign of `GF_sigma`, and added CB dilutes the
response.

| File | Role |
|---|---|
| `gf_mech100_20260620_205743_audit.csv` | Paired $N=100$ hybrid mechanism audit for CB loadings of 1, 5, and 10 wt.%; used by Fig. 10 and Table 3. |
| `gf_simmons_gf_mech100_20260620_205743_h1_ideal.csv` | $N=100$ paired ideal-affine baseline for the 3 wt.% CNT / 1 wt.% CB composition used in Fig. 10. |
| `gf_weaklink_upper_bound.csv` | Compact $N=300$ pure-CNT global CNT-CNT opening table used for the CB=0 reference in Fig. 10. |
| `table3_conduction_pathway_gf.csv` | Machine-readable source table for manuscript Table 3, derived from the audit table, the pure-CNT support table, and the main affine GF references. |

Check the package with:

```bash
python tools/verify_gf_mechanism_support.py
```

Raw per-realization CSVs are not archived here. They are regenerated by the
seeded `reproduce_paper/run_gf_simmons_regime_pub.py` wrapper. Some diagnostic
median columns, such as `power_frac_*_eps0_median`, can be recomputed from the
per-realization `power_frac_*_eps0` fields during support audits; keeping them
out of the frozen paper GF summary schema preserves compatibility with the
`data/reference/gf/` tables. For new user runs, `generate/gauge_factor.py`
does report compact channel-power medians directly in its one-row summary CSV.
